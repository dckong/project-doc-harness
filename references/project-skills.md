# 已有项目 skills 的文档管理

仅在项目已有 skills，或文档仍引用已移走/退役的 skill 时使用本参考。没有 skills 的项目保持原有文档流程，不新增工件、模板、检查要求或建设建议。本参考不规定如何选择、创建、设计或测试 skills；按用户授权管理已有内容的归属与迁移。

## 盘点与可发现性

- 沿项目入口和已有配置查找实际使用的 skills；按需检查 `.agents/skills/` 等隐藏目录，保留项目现有路径。第三方依赖、缓存和历史副本不自动作为当前项目 skills。
- 确认根入口或相关领域入口能引导维护者找到适用 skill。已有路由可用就复用，无须列出所有 skills 或新建专门索引。
- 外部 skill 记录位置和必要访问条件，不把个人安装误记为仓库内已提供的能力。
- 未采用 skills 不构成缺口；已有引用失效仍按断链处理，不能以“当前没有 skills”掩盖。

## 权威来源与信息归属

Skills 沿用主文档的信息角色；它们可以是某项操作流程的权威定义，也可以是引用现有规则的任务投影。不要把每个 skill 的正文复制成一份操作手册。

- 产品目标、架构契约和生产事实由项目指定的权威来源维护，不能仅凭文件位于 docs 或 skills 目录判定权威性。
- 操作流程、验证选择与复用政策可以由已有 skill（包括其 references）完整维护，也可以由专题文档维护，以项目确认的归属为准。Skill 不必只充当其他文档的路由；引用外部事实时用短上下文和链接。
- 脚本承载已有的可执行实现；文档说明用途和输入，不复制实现细节。
- 本次执行的进度、阻塞、环境、验证证据和下一动作沿用项目状态或任务记录。通用 skill 不充当发布日志或任务快照。
- 维护责任沿用相关领域的团队或角色；没有实际需要时，不新增责任登记文件或逐 skill 台账。

## 用户授权的流程权威迁移

用户要求将操作知识集中到已有 skills 时，先明确原正文、新权威及原位置仍需承担的职责，再在授权范围内迁移：

- 将适用流程正文移到指定 skill 或其参考，原文档删除对应重复正文；仍需保留事实、契约或证据的文档继续承担该职责。
- 同步当前入口和引用。历史引用确有需要时保留短跳转或旧锚点，不再维护第二份完整流程；冻结工件按项目规则保留。
- 按既有记录方式注明已变更的信息归属和维护责任，核对迁移前后的条件、步骤与恢复边界。无需为迁移另建永久台账或额外审批层。

这项管理不自动选择新 skills、不规定创作方式，也不借迁移增加原流程没有的执行步骤。

## 运行结果与证据

检查已有 skill 的结果能否回到同一任务及项目的既有记录体系。优先沿用已有产物、导出、计划或运行事实目录，按任务/批次关联；不因存在多个 skills 就为每个 skill 建立一套结果目录。
Skill 目录保存能力定义及其配套资源，本次产物和运行状态放在项目约定的位置。短期输出没有保留价值时不强制归档；可复用或需跨会话恢复的结论保留必要来源与输入标识，不复制整份日志到多处。
本参考不统一各项目的具体路径、记录格式或保留周期，也不要求每次调用创建计划。

## 维护边界

文件、脚本或权威文档移动、替换和退役时，在本次授权范围内同步相关引用与入口。保留仍有价值的历史证据，历史记录指向旧版本不自动构成错误。

发现 skill 与文档冲突时，记录各自内容、版本和证据，判断是否为过期引用、目标/实现差异或待确认选择。未获相应任务授权时，不借文档整理改变 skill 的触发条件、执行步骤、权限边界或验证范围；已有用户授权的迁移和行为调整在其范围内完成，构建方式仍由用户监督。不因本参考自动调用创作工具或生成新 skills。

`SKILL.md` 保持其原有格式，不强加文档的 `doc_type`、`status`、章节模板或复审周期。本参考也不新增 `doc-harness.json` 工件角色。

## 检查与恢复

复用已有链接检查及内容审阅，不因发现 skills 自动运行它们、执行配套脚本或新增应用测试。只有发生相关入口或引用变化时，核实维护者能从项目入口找到该 skill、权威规则及本次任务记录。

现有 `doc_harness.py` 扫描仓库 Markdown 的受支持本地文件链接，包括 `.agents` 下的 Markdown；它不验证链接锚点、skill 格式、触发效果、脚本行为或运行时是否已经加载 skill。项目原有工具的实际覆盖另行说明，不用“检查通过”替代这些判断。
