# 已有项目 skills 的文档管理

项目已使用 skill 或仍引用已迁移、退役的 skill 时，核对其入口、流程归属和产物位置。

## 盘点与可发现性

- 从项目入口和配置确认实际使用的 skills。需要时用 `rg --files --hidden` 查找 `.agents/skills/` 等目录，区分项目正在使用的版本、依赖缓存和历史副本。
- 复用根入口或领域文档中的导航。对外部安装的 skill，注明位置和访问条件。引用失效时按断链处理。

## 权威来源与信息归属

按项目约定选择每个流程的维护位置和负责人。流程正文可以放在 skill、其参考资料或专题文档中，其他入口用简短说明链接到它。产品目标、架构契约和部署事实引用项目指定的来源。脚本的使用说明交代用途和输入，实现细节见脚本。

## 用户授权的流程权威迁移

用户要求把流程移入已有 skill 时：

1. 确认原文、新的维护位置和负责人。将流程正文移到指定 skill 或参考资料中，保留原文档独有的事实、契约和历史证据。
2. 更新入口和引用。仍有人使用的历史链接可保留跳转或旧锚点，冻结的工件按项目规则保存。
3. 核对迁移前后的适用条件、操作步骤、验证范围和恢复方式，并在已有记录中注明归属变化。涉及 skill 的触发条件、权限或执行行为时，按用户授权的范围变更，构建方式由用户监督。

## 运行结果与证据

skill 目录保存能力说明和配套资源。按项目既有的路径、格式和保留周期存放本次任务的产物和证据，用任务或批次关联。进度、阻塞和下一步写入任务记录，需要跨会话使用的结论注明来源和输入标识。

## 维护边界

文件或脚本迁移、替换、退役时，同步当前入口和引用。历史记录指向当时使用的版本。skill 与项目文档说法冲突时，记录双方版本和依据，核实是引用过期、实现有差异，还是尚待决定。保留 `SKILL.md` 自身的格式和元数据。

## 检查与恢复

文档审阅沿用项目的链接检查。入口或引用变更后，从项目入口确认能找到适用的 skill、权威规则和任务记录。`doc_harness.py` 检查仓库 Markdown 中受支持的本地文件链接，包括 `.agents` 下的 Markdown。若任务还涉及 skill 运行效果，按相应验证流程检查触发、加载和脚本行为。
